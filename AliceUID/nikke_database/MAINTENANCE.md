# 1.1.14 日历自动维护

固定匿名GetCalendarDetail只读POST，不借账号凭据；后台独立开关默认开启，Core60秒本地计时，不每分钟发网络请求。日历起止触发小时检查，24小时等待上限，资料就绪后一小时稳定复查再重新排期。事件/周期持久去重，复刻与送角按角色编码核验。先七表并保存，再图片；结构化失败不进入图片阶段。状态/帮助可查询，任务无Bot回调。断点、冷却和周检保持。细节见DEVELOPMENT及handoff。

# 数据库维护与图库补全

NIKKE 通常约 21 天更新一次。插件默认使用 GsCore 共享 scheduler 的唯一 cron：每周五北京时间 02:33（`Asia/Shanghai`），`max_instances=1`、`coalesce=True`。周检用于发现公开表变化，不承诺与游戏发布时刻同步。导入模块、安装插件、读取个人资料均不会启动此处的大图库下载。

Bot 主命令：`nk数据库更新`，立即回复后台启动或正在运行；`nk数据库更新 状态` 查看最近结果；`nk数据库更新 帮助` 查看完整说明。成功、受限未完成、失败冷却、错误都有明确摘要，运行日志每十个尝试记录进度。任务被保留在服务单例中，多个命令及周检串行去重。命令注册使用原生 `SV(..., pm=0)`。

## 主代理集成接口

根模块调用 `commands.setup(config_getter)` 和 `scheduler.setup(config_getter)`。配置 getter 接受下表精确 key 并返回原始值；默认无需额外依赖或安装大图库。普通帮助入口应列出 `nk数据库更新（Bot 主）`。本目录不修改旧资源/缓存服务、根模块或配置默认值。

| 配置键 | 默认值 | 含义 |
| --- | --- | --- |
| DatabaseWeeklyUpdate | true | 周检启用；false 时保留 cron 但 tick 不运行 |
| DatabaseIncludeSkins | true | 默认把公开清单皮肤变体纳入三类队列；false仅补基础图，不证明玩家拥有 |
| DatabaseMaxTasks | 40 | 单批图片尝试数，至少 1 |
| DatabaseMaxDownloadMB | 128 | 单批公开表及图片下载预算，MiB，至少 1 |
| DatabaseMaxDiskMB | 2048 | 本地图 PNG 总容量预算，MiB，至少 1 |
| DatabaseRequestInterval | 2.0 | 所有本批 CDN 请求的最小起始间隔，强制至少 1.5 秒 |
| DatabaseFailureCooldown | 3600 | 失败/拒绝访问后的冷却秒数，至少 60；缓存自身冷却仍生效 |
| DatabaseMaxRunMinutes | 30 | 同一次后台维护连续补全的总时长预算，至少 1 分钟，在图片任务及批次边界检查 |

`DatabaseService(resources, config_getter=None, http=None)` 可注入 `ResourceService` 与离线测试 transport；`run(reason='manual', progress=None)` 返回单批摘要 dict；`run_continuous(...)` 在总时长内连续运行受限批次，后续批次使用 `reason='resume'` 直接读取清单队列、不重拉静态表；`start(..., done=None)` 创建并保留连续后台 task，已有任务返回 None；`get_database(config_getter=None)` 为生产单例。`scheduler.register_scheduler(runner, scheduler)` 接受共享调度器，固定 job id `aliceuid-database-weekly`，重复集成只替换同一 job。

## 持久清单与增量语义

状态文件位于数据根目录下 `database/manifest.json`，通过临时文件加原子替换写入，含角色行 hash、角色到资源及皮肤映射、各静态表文件 hash、PNG 文件 hash、持久任务队列、任务失败重试时间、最后尝试状态、最后一次全部成功时间与最近摘要。表列表动态读取 `ResourceService.TABLES`（兼容当前模块级 TABLES），后续公开装备/技能索引跟随资源服务扩展。

默认补公开角色基础与 `costumes[].costume_index` 变体的头像（SI/icons）、半身像（MI/portraits）和完整立绘（full），只使用清单明确引用的资源ID与索引，不猜测远程ID。管理员显式设 `DatabaseIncludeSkins=false` 可只补基础。顺序为基础SI、MI、full，再皮肤三类。正数索引不表示付费、免费或账号拥有，展示仍以本人接口报告为准。旧清单缺MI会在下次manual/weekly补入；有效文件复用，移出清单的旧资源保留。

开关关闭时，每个入口（含 `resume`、失败冷却返回及运行中的后续任务）都会剔除旧 manifest 中的正数皮肤待办并持久保存，不执行这些下载；已下载的变体文件保留。启用变体补全也不会改变个人卡片默认图片或推断账号所有权。

每轮本地校验现有图片、规范化真实 PNG 并记录 SHA-256；有效图片没有变更任务时不调用 `ImageCache.get`，因此旧头像不会因默认七天 TTL 重新请求。已有预取的 203 个有效基础头像直接采纳。缺失、损坏、新引用的图片，以及已记录皮肤映射发生变化的图片进入队列。静态角色资料行变化记录到摘要；没有资源/皮肤映射变化的文字或数值更新不导致全部图片重下。没有公开逐图版本 hash 的情况下，无法探测同 URL 内容悄然替换；周检不会声称具备此能力。

每成功一项即更新队列和 hash；失败项写持久冷却，重启及再次命令可续跑。表、旧图在网络失败时保留。表 schema 拒绝或更新失败不会假报资料已全部更新；旧表中移除行受现有 ResourceService 合并保留策略约束，摘要以 load_static 实际有效映射为准。

## 预算与公开源限制

默认每批最多 40 次图片尝试、128 MiB 流式下载、图库 PNG 2048 MiB；不会把大型图库打进安装包。命令与周检会在同一次后台任务中连续续传，默认总时长 30 分钟（在图片任务及批次边界检查；已发起的静态表检查或图片请求会结束后再停），批间保持 CDN 请求间隔并记录进度。首装大图库可能跨多个后台任务；达到总时长、磁盘上限、源拒绝、冷却或没有进展时停止，Bot 主可在稍后再次命令续跑。预算耗尽必须显示“尚未全部完成”和剩余项，不能称全部更新。

下载前按缓存单图最大 10 MiB 预留磁盘容量，故图库接近上限时会保守停下；不删除旧资源。流式字节预算包含静态表和图片，最后一个已从网络读到的块可能使计数略越界，但越界数据不会写为有效图片。该预算不代表整个数据目录或操作系统的磁盘配额；下载中其他程序新增文件仍可能导致磁盘错误，错误会保留队列。

生产HTTP客户端独立、剥Cookie/Token/Authorization、禁用环境代理并禁止重定向；只允许公开CDN HTTPS GET、六个已审核官方武器图片完整URL和四个官方徽章完整URL，不扩展到任意官网或账号接口。静态表后先补23项共用基础图标与4项徽章；与人物图共用每批40图、字节/磁盘/时长预算，本地命中不占下载任务。四个官方星/核心/战力PNG按固定URL匿名下载、校验SHA256并缓存；失败冷却后返回已审核内置兜底，明确记录来源。旧已验证素材不重复下载，不在运行时下载JS。POWER数字仍是账号数据和字体，不是数字图API。摘要含pending_base/missing_base，必需基础图缺失时不称整库完成。

401/403/429或HTML/跳转立即停止并持久冷却，不换IP、地址或凭据；普通404/5xx保留原缓存并按失败冷却。公共源不可用不等同于用户登录就能解决，不会将其Cookie发送给CDN。

## 验证边界

模块离线回归用FakeResources/MockTransport覆盖队列、预算、冷却与调度。此前版本在工作区执行过真实公开补全（本轮1.0.02只读复用，没有再次全量下载）：当前203角色、386外观组合，SI/MI/full各386张，合计1158张，23基础图标齐；PNG/来源/哈希审计零错误。使用正式2秒节流与30分钟预算，首次时长到达保存18项，续传18项后队列为0，零失败、零玩家请求、零凭据发送。此覆盖只指当时公共清单，未来游戏变更、跨周cron触发及用户NAS端到端仍须独立验收。
